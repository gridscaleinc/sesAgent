# Secure Talent Match AI 機能検証手順

## 1. 目的

この手順は、Secure Talent Match AI の MVP ワークスペースが、案件要件解析、履歴書インポート、候補者マッチング、人手確認、面接準備、書き出し、監査 / コンプライアンス確認まで一連の業務フローとして動作することを確認するためのものです。

AI の推薦は補助判断として扱い、採用 / 見送りの最終判断は HR 採用責任者または案件責任者が人手で確認します。

## 2. 事前準備

1. プロジェクトルートでローカルサーバーを起動する。

   ```powershell
   npm start
   ```

2. ブラウザで次の URL を開く。

   ```text
   http://127.0.0.1:4173/
   ```

3. 初期画面の左ナビゲーション、上部ボタン、案件要件フォームが日本語で表示されていることを確認する。

期待結果:

- 左ナビゲーションに「案件要件」「履歴書インポート」「マッチング結果」「候補者詳細」「面接質問」が表示される。
- ヘッダーに「MVP ワークスペース」「案件要件解析」が表示される。
- 中国語の主要 UI ラベルが残っていない。

## 3. 案件要件解析

1. 「案件要件」画面で、案件名、JD / 案件要件、業界、勤務地、参画可能日、契約形態を確認する。
2. 「解析して条件を更新」を押す。
3. AI 解析結果、重み、マッチング準備チェックリスト、面接確認ポイントを確認する。
4. 「要件条件を確認」を押す。

期待結果:

- 要件条件の確認状態が更新される。
- 重みを変更できる。
- 監査タイムラインに要件解析または要件確認のイベントが追加される。
- 推薦や判断に「自動採用」「自動見送り」のような確定表現が表示されない。

## 4. 履歴書インポート

1. 左ナビゲーションで「履歴書インポート」を開く。
2. 「サンプル履歴書をインポート開始」を押す。
3. インポート進捗、総数、成功、失敗、未処理の表示を確認する。
4. 「ATS CSV テンプレートをダウンロード」を押す。

期待結果:

- 120 件のサンプル候補者プロフィールが生成される。
- インポート状況が成功として表示される。
- ATS CSV テンプレートがダウンロードされる。
- CSV フィールドプレビューが表示される。

## 5. マッチング結果と絞り込み

1. 「マッチング結果」を開く。
2. 「マッチングを再実行」を押す。
3. 候補者カード、総合スコア、推薦レベル、人工判断を確認する。
4. 検索欄に `Java` などのキーワードを入力する。
5. 推薦レベル、人工判断、ショートリストのみの絞り込みを順に試す。
6. 並び順を「スキル適合」「案件経験」「言語力」などに切り替える。
7. 「絞り込み解除」を押す。

期待結果:

- 絞り込み概要に「該当 n/N 名」「現在の絞り込み」「並び順」が表示される。
- 推薦レベルの値は「優先確認推奨」「面接確認推奨」「人手レビュー推奨」「優先度低」で統一される。
- 絞り込み解除後、候補者全体に戻り、並び順は「総合スコア」に戻る。

## 6. ショートリストと人工判断

1. 候補者カードの「ショートリストに追加」を押す。
2. ショートリスト数が増えることを確認する。
3. 「ショートリストを面接へ進めるに設定」を押す。
4. 人工判断の分布を確認する。
5. 人工判断の分布項目をクリックし、候補者一覧が絞り込まれることを確認する。
6. 「人工判断サマリー CSV を書き出し」を押す。

期待結果:

- ショートリスト候補者の人工判断が「面接へ進める」になる。
- 人工判断分布のクリックで該当候補者だけが表示される。
- CSV 書き出しが実行され、監査イベントが追加される。

## 7. 候補者詳細とプロフィール補正

1. 候補者カードの「詳細を見る」を押す。
2. 候補者詳細、スコア内訳、強み、ギャップ、リスク、証拠を確認する。
3. プロフィール補正フォームで候補者名、職種、スキルタグ、分項スコア、強み、ギャップ、リスクを編集する。
4. 「プロフィール補正を保存」を押す。
5. 人手確認メモを入力し、「メモを保存」を押す。

期待結果:

- 編集内容が候補者詳細に反映される。
- マッチングスコアが再計算される。
- メモとプロフィール補正が監査タイムラインに記録される。

## 8. 面接準備

1. 「面接質問」を開く。
2. 「面接準備表を生成」を押す。
3. 技術質問、案件深掘り、リスク確認の質問を確認する。
4. 「面接準備表 CSV を書き出し」を押す。
5. ショートリストがある状態で「ショートリスト面接パックを生成」を押す。
6. 「ショートリスト面接パック CSV を書き出し」を押す。

期待結果:

- 質問は案件要件、候補者の経験、リスク、証拠に紐づいている。
- ショートリスト面接パックは、ショートリストに入れた候補者だけを対象にする。
- CSV 書き出しが実行される。

## 9. セキュリティ / コンプライアンス

1. 画面右側または下部の AI 処理設定を確認する。
2. モデル、プロンプトバージョン、マスキング強度を変更する。
3. 「接続確認」を押して Mock API 状態を確認する。
4. 「マッチング結果を同期」を押す。
5. マスキングプレビュー、コンプライアンスチェック、MVP 受入チェックリストを確認する。

期待結果:

- Mock API 状態が成功として表示される。
- API 同期後も候補者カードと詳細が表示される。
- マスキングプレビューにメール、電話、会社名などの残留確認結果が表示される。
- コンプライアンスチェックは AI 補助判断、人手確認、証拠、リスク追問の観点を含む。

## 10. ワークスペースとレポート書き出し

1. 「パイロットデモを一括準備」を押す。
2. 120 件の候補者、前 5 名のショートリスト、人工判断が生成されることを確認する。
3. 次の書き出しボタンを順に押す。
   - 現在の絞り込み CSV
   - ショートリスト CSV
   - ショートリスト比較 CSV
   - 品質 CSV
   - 監査サマリー
   - コンプライアンスレポート
   - パイロットレポート
   - パイロット納品パック
   - ワークスペース JSON
4. サンプルワークスペース JSON をダウンロードする。
5. ダウンロードしたワークスペース JSON をインポートする。
6. 「ローカル保存をクリア」を押し、再読み込み後にサンプルデータへ戻ることを確認する。

期待結果:

- 各 CSV / JSON のダウンロードが実行される。
- 書き出し操作が監査タイムラインに記録される。
- workspace schema の必須項目が欠けた JSON をインポートした場合、現在のワークスペースは上書きされない。

## 11. 自動チェック

手動検証後、次のコマンドを実行する。

```powershell
npm test
npm run check
```

期待結果:

- すべてのテストが成功する。
- JavaScript の構文チェックが成功する。
- Mock API、OpenAPI、workspace schema、サンプル workspace の整合性チェックが成功する。

## 12. 合格基準

- 主要 UI が日本語で表示される。
- 案件要件からショートリスト、面接準備、書き出しまでの MVP フローが通る。
- 推薦レベルと人工判断の用語が画面、CSV、監査で一貫している。
- AI は補助判断として表示され、自動採用 / 自動見送りの確定表現を使っていない。
- ローカル保存、ワークスペース JSON、Mock API が破綻なく動作する。
