# SES Agent 主界面 UI 规格 v1

状态：视觉方向已确认，等待产品代码实施
确认日期：2026-08-24（JST）
主验收画布：1440 × 1024
Figma：[SES Agent · 主界面改造规格 v1](https://www.figma.com/design/xKWgWZLFJx4FIwiXlZ0HG3/SES-Agent?node-id=2-2)

## 1. 目标与终点

SES Agent 是应用打开后的默认主入口，也是用户持续处理案件、候选人、匹配和面试工作的主要工作台。

v1 的终点是：用户进入应用后，可以在一个持续存在的任务中完成自然语言对话、查看当前业务上下文、触发受控本地 Tool、确认权威业务结果，并一键进入对应的结构化业务页面继续查看或修改。

本规格固定以下产品边界：

- Agent 负责理解意图、承载连续对话、组织结果和引导下一步。
- 案件、候选人、匹配结果、审核中心、面试日程等结构化页面继续作为事实、证据、编辑和人工决策的权威入口。
- 本次只改造 Agent 主界面的信息架构和交互表达，不增加新的 Domain Tool、权限、外部写入能力或业务流程。
- 不建设通用插件系统、自由工作流编辑器、动态代码组件或多工作台平台。
- 不把主界面重新做成业务指标 Dashboard；指标仅在确实影响当前任务时作为上下文出现。

## 2. 设计依据与优先级

发生冲突时按以下顺序执行：

1. 已确认的 Figma 最终目标稿决定视觉层级、密度和布局方向。
2. 本文档决定交互语义、状态规则和验收结果。
3. 现有结构化业务页面和持久化数据决定业务事实。
4. 现有组件与样式可以复用，但不能以“当前已经这样实现”为理由保留低于本规格的字号、重复内容或错误的会话语义。

Figma 当前状态：`01 · Final UI` 已包含最终目标稿；`02 · Layout & Visual Spec` 与 `03 · Interaction & Acceptance` 已建立页面骨架。由于 Figma Starter 套餐触发 MCP 调用上限，详细规格暂以本文档为权威来源，额度恢复后再同步到对应页面。

## 3. 页面信息架构

主界面只保留六个一级区域：

| 区域 | 作用 | 是否固定 |
| --- | --- | --- |
| 任务栏 | 切换业务任务、显式新建任务 | 固定在左侧 |
| 工作区标题栏 | 展示 Agent、当前任务标题和隐私状态 | 固定在顶部 |
| 当前上下文栏 | 展示案件、候选人和当前业务结果 | 固定在标题栏下方 |
| 消息流 | 展示用户输入、Agent 回复和结构化业务块 | 独立滚动 |
| 后续操作区 | 展示与最近权威结果直接相关的 1–3 个动作 | 跟随消息流 |
| 输入区 | 继续当前任务、附加简历、选择模型、发送或停止 | 固定在底部 |

不在主界面顶部继续展示“有效案件、可匹配人才、待审核、处理中”等常驻指标条。这些信息属于业务总览，只有在当前任务需要时由 Agent 或上下文块呈现。

## 4. 固定布局

### 4.1 1440 × 1024 主验收尺寸

| 元素 | 规格 |
| --- | --- |
| 应用画布 | 1440 × 1024，背景 `#FBFBFC` |
| 左侧任务栏 | 252 px，背景 `#F5F6F8`，右边界 1 px |
| 主工作区 | 1188 px，纵向 Flex 布局，禁止整体页面滚动 |
| 标题栏 | 高 58 px，左右内边距 28–32 px |
| 当前上下文栏 | 高 44 px，位于标题栏下方，单行显示 |
| 消息内容列 | 最大宽度 840 px，水平居中 |
| 用户消息最大宽度 | 内容列的 76%，上限约 640 px |
| 结果回执 | 与消息内容列同宽或按内容收缩，最小高 104 px |
| 输入区 | 宽 840 px，距窗口底部 24 px，最小高 112 px |
| 消息流底部留白 | 至少为输入区高度加 40 px，避免最后一条消息被遮挡 |

### 4.2 响应式边界

| 窗口宽度 | 行为 |
| --- | --- |
| ≥ 1180 px | 任务栏 252 px，内容列最大 840 px |
| 900–1179 px | 任务栏收窄至 220 px，内容列按剩余宽度缩放 |
| < 900 px | 任务栏变为覆盖式抽屉；主工作区占满宽度 |

无论窗口尺寸如何变化，输入区不得覆盖消息内容；正文不得缩小到 12 px 以下。

生产字体栈沿用项目现有设置：

中文环境继续允许 `PingFang SC`、`Hiragino Sans GB`、`Microsoft YaHei`、`Noto Sans SC` 作为系统回退。

| 角色 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 当前任务主标题 | 24 / 34 px | 650–700 |
| 区域标题、结果标题 | 16 / 24 px | 650–700 |

### 5.3 间距和圆角

- 基础间距序列：4、8、12、16、24、32 px。
- 任务行高度：52–58 px。
- 普通按钮最小高度：36 px；主业务动作建议 40 px。
- 用户消息圆角：14–16 px。
- 业务结果回执圆角：12 px。
- 输入区圆角：18 px。
- 阴影只用于固定输入区；其他区域优先使用间距、分隔线和浅色底。
- 禁止卡片嵌套卡片，也不把每条普通列表项都做成独立卡片。

## 6. 组件规格

### 6.1 `TaskRail`

任务栏标题使用“任务”，不再使用“历史会话”作为主心智。

- 顶部只有一个显式“新建任务”按钮。
- 新建按钮为普通描边按钮，不与输入区和业务结果主动作争夺注意力。
- 任务列表使用连续列表结构；普通行不带独立卡片阴影。
- 选中项使用浅蓝背景和左侧 3 px 选中轨道。
- 每个任务必须有业务化标题，避免反复出现“总结一下”这类无法区分的名称。
- 副标题由“更新时间 + 当前状态”组成，例如“刚刚 · 已登记”。
- 分支、编辑重发和同一任务的普通追问不得生成新的可见任务行。

任务标题优先级：

1. 当前案件名 + 当前业务目标，例如“支付平台改造 · 面试安排”。
2. 候选人 + 当前动作，例如“RESUME_1 · 简历评估”。
3. 无业务上下文时使用第一条用户输入的语义摘要。

### 6.2 `WorkspaceHeader`

- 左侧显示小号 `SES Agent` 和当前任务主标题。
- 右侧只保留隐私状态“仅发送脱敏内容”。
- 不在标题栏放业务指标、模型价格或工程状态。
- 标题必须截断而不是挤压右侧隐私状态。

### 6.3 `ContextBar`

上下文栏只展示当前任务最关键的持久上下文：

- 案件：名称和版本。
- 候选人：持久标识或已确认姓名。
- 当前业务结果：例如“面试已登记”。
- 直接入口：`打开案件`、`打开简历`。

上下文栏不是可关闭的临时提示。只要任务仍关联对应业务对象，重新打开任务或重启应用后都必须恢复。

### 6.4 `UserMessage`

- 右对齐，浅灰蓝背景，正文 15 px。
- 悬停或键盘聚焦后显示“复制”和“编辑并重新发送”。
- 复制不改变任何状态。
- 编辑并重新发送必须保留原对话和已执行副作用；新执行作为当前任务内的修订分支，不在任务栏增加新任务。
- 编辑期间只锁定当前编辑器和当前请求相关操作，不能导致整个界面永久灰化。
- 无悬停能力的设备始终显示两个操作。

### 6.5 `AssistantMessage`

- Agent 的自然语言回答直接排版在消息流中，不默认放进卡片。
- 只说明结论、必要依据和下一步，不重复结构化业务块中已经存在的完整内容。
- Markdown 支持标题、列表、代码、链接和受信任的系统动作块。
- 模型名是低优先级信息，默认不在每条回复旁持续强调。

### 6.6 `SystemReceipt`

本地 Tool 成功改变业务状态后，必须渲染一张权威业务结果回执。

面试回执示例：

- 标题：`面试已登记`。
- 状态：`已保存`。
- 元数据：`2026-08-26 14:00 JST · 50 分钟 · Zoom`。
- 敏感信息：只显示 `Zoom 链接已在本机保存`。
- 主动作：`打开面试日程`。
- 次动作：`修改`。

回执规则：

- 业务回执来自本地 Tool 的权威结果，不依赖远端 AI 是否成功整理自然语言总结。
- 只有确认持久化记录存在后才能显示“已登记”“已保存”等成功状态。
- 如果本地 Tool 失败，不得展示成功回执，也不得生成虚构记录标识。
- 如果 Tool 已成功而 AI 流式整理失败，保留权威回执，不向用户显示“AI 流式整理失败”“最终费用仍以……为准”等干扰业务确认的工程提示；详细错误进入日志和可诊断状态。
- 回执只使用一个容器，不在外层 Agent 卡片里再嵌套业务卡片。

### 6.7 `NextActionRow`

- 紧跟最近一张权威回执。
- 最多显示三个与该业务对象直接相关的动作。
- 面试成功后的默认动作：`准备面试问题`、`查看候选人简历`、`安排下一轮`。
- 只允许跳转到已有结构化页面或调用已有受控动作，不引入新的权限路径。
- 没有明确相关动作时不显示，不使用占位按钮填满界面。

### 6.8 `Composer`

- 输入区上方显示“发送到：{当前任务标题}”。
- 该文案必须使用当前可见任务的稳定任务 ID，而不是临时草稿 ID。
- 输入占位文字：`继续询问当前案件、候选人或面试…`。
- 底部保留附件、低强调模型选择、键盘提示和发送按钮。
- `Enter` 发送，`Shift+Enter` 换行。
- 请求进行中时发送按钮变为停止按钮；停止是止损操作，不承诺免费或退款，但该说明不应常驻占据主界面。
- 模型选择属于高级控制，视觉优先级低于输入和发送。

### 6.9 `ResumeImportBlock`

用户从候选人卡片点击“导入到会话”后，必须在当前任务消息流中追加一个本地导入块。

导入块至少显示：

- `简历已导入当前任务`。
- 安全候选人标识或已确认姓名。
- 文档格式和导入时间。
- `打开简历` 操作。

导入块及其候选人上下文必须加密持久化；重启应用、重新打开任务和任务内编辑重发后仍可恢复。不能从设备级候选人列表猜测“用户说的这个人”。

## 7. 任务、会话和分支语义

用户可见层只使用“任务”。内部可以继续保留 conversation、revision、branch 等技术结构，但不得直接映射为左侧重复任务。

### 7.1 普通继续对话

1. 用户选择一个任务。
2. 输入区显示该任务标题。
3. 每次发送都复用当前稳定任务 ID。
4. Main 返回更新后的任务快照。
5. 左侧只更新原任务的标题、时间、状态和消息数量，不新增任务。

### 7.2 显式新建任务

只有以下操作可以生成新的任务栏项目：

- 点击“新建任务”。
- 用户明确选择“从这里开始新任务”，且界面展示了该动作的含义。

刷新 Bootstrap、接受 Main 返回快照、流式事件结束、Tool 执行成功、附件分析完成，都不能隐式创建可见任务。

### 7.3 编辑并重新发送

- 原消息、原回复和已执行的本地副作用留在原修订中。
- Main 根据受信任的源任务、revision 和目标消息复制前缀，再执行编辑后的输入。
- 新修订继承任务根标识，因此左侧仍显示为同一个任务。
- 默认不复制临时附件；持久化的简历导入上下文必须继承。
- 请求结束或失败时必须在 `finally` 中恢复可交互状态，清理编辑态、pending 态和分支预览态。
- Sales Agent 任务只能通过 `executeAgentTurn` 保存执行结果；Renderer 不得退回通用 `ai-conversations:save` 路径。

## 8. 上下文处理

发送给 AI 的上下文按以下顺序构建：

1. 当前任务中已持久化的用户与 Agent 消息。
2. 当前任务持久化的简历导入块和候选人投影。
3. 当前选中案件及其最小必要投影。
4. 最近一次匹配、审核或面试 Tool 的权威结果。
5. 当前附件的安全预览，仅限本次请求。

上下文规则：

- 不从其他任务借用候选人、案件或附件。
- 不以设备级“最近一条数据”替代当前任务缺失的证据。
- 分支只能继承源任务已持久化且位于受信任前缀中的上下文。
- 发送到远端的内容继续经过最小化投影和脱敏；完整简历、会议密码和本地文件路径不进入普通回答文本。
- 当候选人信息存在时，Agent 不得退化为“未提供候选人姓名、履历”等通用回答。

## 9. 面试登记行为

- 时间输入按用户当前时区解释；本产品当前默认是 JST。
- 传入持久化层前必须转换为合法 ISO datetime，并保留明确时区语义。
- 时长使用正整数分钟；界面可以推荐 30、45、60、90，但不能拒绝 50 分钟等合理值。
- Zoom URL 只在本机受保护字段中保存；消息流、日志摘要和回执不显示完整 URL 或密码。
- Tool 返回成功后，必须立即从持久化存储读取或通过返回快照确认记录存在，再生成成功回执。
- `打开面试日程` 必须导航到包含刚创建记录的面试管理页面；路由成功但记录不可见不算验收通过。

## 10. 状态矩阵

| 状态 | 消息流表现 | 输入区 | 允许操作 |
| --- | --- | --- | --- |
| 空任务 | 简短欢迎语和 2–3 个起始建议 | 可输入 | 导入简历、选择案件、提问 |
| 就绪 | 显示历史消息和当前上下文 | 可输入 | 发送、复制、编辑重发 |
| 附件处理中 | 附件托盘显示解析状态 | 暂时限制附件操作 | 可取消尚未导入附件 |
| 正在理解 | 一行低强调运行状态 | 停止按钮 | 停止 |
| Tool 执行中 | 显示受控本地操作名称，不泄露内部计划 JSON | 停止按钮 | 停止或等待 |
| AI 流式回复 | 逐步显示回答 | 停止按钮 | 停止 |
| 需要信息 | 一张结构化缺失字段块 | 可输入 | 补充字段 |
| Tool 成功 | 权威回执 + 相关跳转 | 可继续输入 | 打开结构化页面 |
| Tool 失败 | 一条可理解错误，不显示原始校验正则或堆栈 | 可重试 | 修改输入、重试 |
| 云端未连接 | 保留本地上下文和只读历史 | 隐藏普通输入 | 连接受管账号、打开本地业务页 |

缺失字段状态只能出现一次：不得同时渲染同样的 Agent 段落和结构化缺失字段卡片。

## 11. 系统访问按钮映射

| 业务结果 | 主按钮 | 目标 |
| --- | --- | --- |
| 案件已导入 / 已选择 | 打开案件 | 案件详情 |
| 简历已导入 | 打开简历 | 候选人 / 简历详情 |
| 匹配完成 | 打开完整匹配 | 匹配结果页 |
| 等待人工确认 | 打开审核中心 | Review Center |
| 面试已登记 | 打开面试日程 | 面试管理 / 日历 |
| 后台任务处理中 | 打开任务 | 任务中心 |

系统访问按钮由受信任的结构化 block 类型生成，不允许远端模型输出任意路由、文件路径或外部 URL 后直接执行。

## 12. 可访问性和键盘

- 所有可点击控件都必须有可见焦点状态和明确的 `aria-label`。
- 图标按钮最小热区 32 × 32 px；关键业务按钮不低于 36 px 高。
- 文字与背景对比度满足 WCAG AA。
- 任务切换后焦点不自动跳到页面外；输入框保持合理焦点策略。
- 用户消息操作不能只依赖鼠标悬停，键盘聚焦和无悬停设备同样可用。
- 动画遵守 `prefers-reduced-motion`；运行状态不依赖颜色单独表达。

- 用户消息复制 / 编辑重发：`UserMessageEditor` 与 `executeAgentTurn` 路径
- 结构化业务结果：`BlockView` 及 system-access block
- 会话与导入持久化：现有 SQLCipher conversation / conversationImports 路径

实现时不创建第二套会话存储、第二套 Tool 执行路径或新的前端路由协议。

## 14. 验收场景

### A. 默认入口

- 启动应用后默认进入 SES Agent，而不是总览或传统匹配页。
- 当前任务存在时恢复最近任务；没有任务时显示空任务状态。

### B. 任务连续性

- 在同一任务连续发送 5 条普通消息，左侧仍只有 1 条对应任务。
- 任务更新时间和消息数量可以更新，但任务根标识不变。
- 只有点击“新建任务”后左侧才增加 1 条任务。

### C. 用户消息操作

- 每条历史用户消息都可以复制。
- 编辑历史输入并重新发送不会调用通用 `ai-conversations:save`。
- 请求成功、失败或取消后，页面都恢复可交互，不出现永久灰化。
- 编辑重发产生的修订不显示成新的左侧任务。

### D. 简历上下文

- 从候选人卡片点击导入后，当前消息流立即出现简历导入块。
- 重新打开任务或重启应用后，导入块和候选人上下文仍存在。
- 后续询问“这个人是谁”时，Agent 使用当前任务的持久化简历信息回答。
- 编辑重发后仍保留持久化简历上下文，但不自动继承临时附件。

### E. 面试登记

- 输入合法日期、14:00、50 分钟和 Zoom 链接后可以成功登记。
- 持久化记录的时间是合法 ISO datetime，并在 UI 中显示为 JST。
- 成功回执显示 50 分钟，不强制改成预设时长。
- 点击“打开面试日程”后能看到刚创建的同一条记录。
- 消息流中不显示完整 Zoom URL、密码或原始校验正则。

### F. 权威结果与失败语义

- 本地 Tool 成功、AI 整理失败时仍显示权威回执，不显示干扰性的流式整理失败横幅。
- 本地 Tool 未保存记录时，不得回复“已登记”。
- Tool 校验失败只显示可行动的业务提示，例如“日期格式无法识别，请补充年月日和时区”。

### G. 业务跳转

- 案件、简历、匹配、审核、面试和后台任务结果都能生成对应系统访问按钮。
- 按钮只导航到受信任的内部目标，不能由普通 Markdown 链接获得系统权限。

### H. 视觉验收

- 1440 × 1024 下与 Figma 最终目标稿的区域比例、信息层级和密度一致。
- 正文不低于 15 px，次要信息不低于 12 px。
- 没有顶部指标条、重复成功段落、重复缺失字段提示或卡片嵌套。
- 输入区、最后一条消息和业务回执在常见窗口高度下互不遮挡。

## 15. 完成标准

满足以下全部条件后，v1 才算完成：

- 上述 A–H 验收场景通过。
- 现有会话持久化、简历导入、面试登记和内部跳转没有回归。
- 结构化页面仍是业务事实和编辑的权威入口。
- 未引入新的 Tool、权限模型、插件执行能力或外部写入路径。
- 已完成打包后的人工验收，并记录验证版本。
