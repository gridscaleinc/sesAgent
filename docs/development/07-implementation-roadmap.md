# Secure Talent Match AI MVP Implementation Roadmap

## 1. 阶段 0：开发准备

目标：将产品说明书转化为可开发的基础规格。

交付物：

- MVP 页面与流程确认。
- 数据模型 V0.1。
- API 草案 V0.1。
- 评分模型 V0.1。
- 测试样本需求清单。

完成标准：

- 团队能根据文档启动前后端、AI 和测试工作。
- 已确认第一版不做完整 ATS、自动录用/淘汰和 ATS 连接器。

## 2. 阶段 1：单机 PoC 基础能力

目标：跑通单机端到端流程。

开发内容：

- 本地 Web 工作台基础页面：项目需求、简历导入、匹配结果、候选人详情、面试问题。
- SQLite 数据库。
- 本地文件存储。
- PDF / Word / CSV 文本抽取。
- 简历解析任务状态。
- 项目需求解析和人工编辑。

完成标准：

- 可创建 1 个项目需求。
- 可导入 50-200 份简历。
- 每份简历可看到解析状态和失败原因。
- 解析成功的简历能保存结构化字段和原文证据。

## 3. 阶段 2：匹配与解释

目标：生成可解释候选人短名单。

开发内容：

- 规则权重评分。
- FAISS / Chroma 向量检索。
- 本地 Ollama + Qwen / Llama 模型调用。
- 总分、分项分、推荐理由、风险点和人工确认建议。
- 匹配结果列表和详情页。

完成标准：

- 1 个项目需求 + 50-200 份简历可在 5 分钟内完成匹配。
- 每个候选人有总分、分项分、证据、缺口和风险点。
- 页面不出现自动录用或自动淘汰表达。

## 4. 阶段 3：面试准备与导出

目标：让 HR 能把匹配结果用于真实工作流。

开发内容：

- 面试问题生成。
- 技术验证题、项目复盘题、风险追问和评分表。
- 短名单 CSV 导出。
- 面试准备表导出。
- 导出审计日志。

完成标准：

- 每个风险点至少生成一个追问。
- 面试问题引用项目需求或候选人真实经历。
- 导出文件包含项目需求 ID、候选人 ID、总分、分项分、推荐理由、风险点和生成时间。

## 5. 阶段 4：安全与试点强化

目标：让 MVP 具备进入 1-2 家客户试点的基础条件。

开发内容：

- 脱敏 API 模式。
- 模型版本、提示词版本和权重版本记录。
- 操作审计日志。
- 基础权限角色。
- 部署脚本和环境配置说明。

完成标准：

- 外部 API 调用前敏感字段已脱敏。
- 审计日志覆盖导入、解析、评分、权重修改和导出。
- 客户可选择纯本地模式或脱敏 API 模式。

## 6. 阶段 5：试点后扩展

目标：基于试点反馈决定企业化方向。

候选扩展：

- PostgreSQL 替换 SQLite。
- Qdrant 替换 FAISS / Chroma。
- 多用户权限。
- ATS 连接器。
- 日文简历解析评测集。
- 更完整的偏见审计和合规报告。

进入条件：

- MVP 已在真实或接近真实的简历样本上验证价值。
- HR 能理解并信任评分解释。
- 客户愿意将真实简历导入本地 AI 工作台。
