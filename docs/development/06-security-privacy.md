# Secure Talent Match AI Security and Privacy

## 1. 安全定位

数据安全是 Secure Talent Match AI 的产品定位之一。MVP 默认采用本地优先处理，候选人原始数据、结构化字段、评分记录和审计日志保存在客户控制的环境中。

系统提供 AI 辅助判断，不提供自动录用或自动淘汰决策。

## 2. 数据分类

| 数据类型 | 示例 | 默认处理 |
| --- | --- | --- |
| 候选人身份信息 | 姓名、电话、邮箱、地址 | 本地保存，外部 API 调用前脱敏 |
| 职业经历信息 | 公司名、项目名、职责、技术栈 | 本地保存，敏感实体可脱敏 |
| 薪资与可用性 | 希望薪资、到岗时间、地点 | 本地保存，导出需审计 |
| 项目需求 | JD、客户行业、工作地点 | 本地保存，API 调用按配置处理 |
| AI 输出 | 摘要、评分、理由、风险点 | 保存版本和证据引用 |
| 审计日志 | 操作者、导入、评分、导出 | 本地保存，支持复核 |

## 3. 本地优先要求

- 简历原始文件默认存储在客户环境内。
- 结构化字段、向量索引、评分结果和日志默认本地保存。
- 本地 LLM 作为优先验证路径。
- 外部 API 模式必须可关闭。
- 用户界面应明确展示当前 AI 处理模式：本地模式或脱敏 API 模式。

## 4. 脱敏要求

外部 API 调用前必须替换以下信息：

- 姓名。
- 电话。
- 邮箱。
- 地址。
- 公司名。
- 项目名。
- 薪资。

推荐占位符格式：

| 原始类型 | 占位符 |
| --- | --- |
| 姓名 | `[CANDIDATE_NAME]` |
| 电话 | `[PHONE]` |
| 邮箱 | `[EMAIL]` |
| 地址 | `[ADDRESS]` |
| 公司名 | `[COMPANY]` |
| 项目名 | `[PROJECT]` |
| 薪资 | `[SALARY]` |

脱敏文本和原始文本需要分别保存，评分证据展示默认使用可控片段。

## 5. API 使用限制

当启用外部 API 模式时：

- 不发送候选人完整原始简历。
- 不发送候选人身份信息。
- 不发送未脱敏的公司名、项目名和薪资。
- 不允许将 API 输出作为自动招聘决策。
- 审计日志必须记录 API 模式、模型版本、调用时间和任务 ID。

## 6. 审计日志

以下行为必须记录：

- 项目需求创建、修改和确认。
- 条件权重修改。
- 简历导入和解析失败。
- 匹配任务运行。
- 模型版本或提示词版本变化。
- 候选人详情查看。
- 短名单和面试准备表导出。

审计记录至少包含操作者、行为类型、目标对象、发生时间和关键元数据。

## 7. 导出控制

MVP 支持导出短名单 CSV 和面试准备表。导出内容应包含生成时间和项目需求 ID，便于人工回写 ATS 或内部复核。

导出行为必须写入审计日志。企业试点阶段可加入角色权限、导出水印和下载过期时间。

## 8. 合规提示

招聘 AI 场景可能涉及自动化雇佣决策、偏见审计和高风险 AI 管理要求。产品文案、页面提示和导出内容应统一表达为“AI 辅助判断”。

系统必须避免：

- 将 AI 分数表述为合格或不合格判定。
- 隐藏评分依据和证据。
- 使用与岗位无关或受保护属性作为评分依据。
- 让用户误以为系统可以替代人工招聘决策。
