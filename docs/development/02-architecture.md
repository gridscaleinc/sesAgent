# Secure Talent Match AI MVP Architecture

## 1. 架构原则

- 本地优先：候选人原始数据默认保存在客户环境内。
- 可解释：所有评分和建议都要能追溯到需求条件与简历证据。
- 可替换：数据库、向量库和模型层允许从 PoC 组件平滑升级到企业组件。
- 不替代 ATS：MVP 通过 CSV / 简历包导入与导出结果协作。

## 2. 推荐技术路径

| 层级 | 单机 PoC 默认 | 企业试点升级 |
| --- | --- | --- |
| 前端 | 本地 Web 工作台 | 同 PoC，可加入权限与多用户 |
| 后端 | Python / Node 服务 | Python / Node 服务 + 队列 Worker |
| 数据库 | SQLite | PostgreSQL |
| 文件存储 | 本地文件系统 | 客户环境对象存储或受控文件目录 |
| 向量检索 | FAISS / Chroma | Qdrant |
| 模型 | Ollama + Qwen / Llama | 本地 LLM + 可选脱敏 API |
| 导入集成 | CSV / 简历包 | ATS 连接器 |

## 3. 逻辑组件

### Web 工作台

提供项目需求、简历导入、匹配结果、候选人详情和面试问题页面。所有 AI 输出都必须允许人工确认或备注。

### API 服务

负责接收前端请求、保存项目需求、管理导入任务、触发匹配任务、读取候选人详情、生成面试题和导出结果。

### 解析 Worker

负责 PDF / Word / CSV 解析、字段抽取、脱敏、向量化和入库。解析失败应记录错误，不中断整个批次。

### 匹配 Worker

负责读取项目需求和候选人画像，执行规则权重评分、语义匹配和 LLM 解释生成，输出总分、分项分、证据、缺口和风险点。

### AI 编排层

封装本地 LLM 和可选 API 模式。外部 API 模式必须先经过脱敏层，不允许发送候选人完整身份信息和完整敏感原文。

### 审计层

记录模型版本、评分时间、操作者、权重变化、导入行为和导出行为，便于内部合规与事后复核。

## 4. 数据流

1. HR 在项目需求页输入 JD。
2. API 服务保存原始 JD，并调用 AI 编排层生成结构化条件。
3. HR 修改并确认条件权重。
4. HR 导入简历文件或 ATS CSV。
5. 解析 Worker 抽取字段，保存原文、结构化数据和证据片段。
6. 脱敏层生成安全文本，用于可选 API 调用。
7. 向量检索层为项目需求和候选人经历建立索引。
8. 匹配 Worker 生成候选人排序和解释。
9. HR 查看详情、生成面试问题并导出结果。
10. 审计层记录关键操作和模型输出版本。

## 5. 部署模式

### 单机 PoC

- 前端、后端、SQLite、FAISS / Chroma 和本地 Ollama 运行在同一台机器。
- 适合导入 50-200 份简历并验证短名单质量。
- 重点验证价值、速度、解析质量和解释可信度。

### 企业试点

- 后端服务、数据库、向量库和文件存储部署在客户控制的环境中。
- PostgreSQL 保存结构化数据和审计日志。
- Qdrant 提供更稳定的向量检索能力。
- 可加入多用户、权限、导出控制和更完整的审计策略。

## 6. 关键非功能要求

- 200 份简历的 MVP 匹配任务目标完成时间为 5 分钟内。
- 候选人原始文件和解析结果默认不离开客户环境。
- 任意 AI 建议都不得作为自动录用或自动淘汰结果。
- 模型、提示词、权重和导出行为需要可追溯。
