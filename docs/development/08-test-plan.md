# Secure Talent Match AI MVP Test Plan

## 1. 测试目标

验证 Secure Talent Match AI MVP 是否能在本地优先、安全可解释的前提下，完成从项目需求、简历导入、匹配排序到面试准备和导出的端到端流程。

## 2. 功能测试

| 场景 | 验证点 |
| --- | --- |
| 创建项目需求 | 可保存 JD、项目信息和状态 |
| AI 解析需求 | 可生成硬性条件、加分条件、权重、风险项和面试验证点 |
| 人工编辑条件 | 修改后的权重和条件被匹配任务使用 |
| 上传简历 | 支持 PDF、Word、CSV 和文件夹导入 |
| 查询导入状态 | 可查看总数、成功数、失败数和失败原因 |
| 运行匹配任务 | 可生成候选人排序和推荐级别 |
| 查看候选人详情 | 可查看 AI 摘要、分项评分、证据、缺口和风险点 |
| 生成面试问题 | 可生成技术验证题、项目复盘题、风险追问和评分表 |
| 导出结果 | 可导出短名单 CSV 和面试准备表 |

## 3. 解析质量测试

测试样本：

- 20-50 份匿名日文简历样本。
- 覆盖履歴書、職務経歴書、PDF、Word 和 ATS CSV。
- 包含 IT / SES 常见技术栈和项目经历。

验收标准：

- 能抽取候选人基本信息、技能、项目经历、工作年限、语言能力和可用性。
- 解析失败的文件不影响整个批次。
- 每条关键结构化信息能追溯到简历证据片段。

## 4. 匹配解释测试

测试场景：

- Java 后端项目，要求 5 年以上经验、支付系统经验和日语沟通能力。
- 候选人 A 明确满足核心条件。
- 候选人 B 技能满足但行业经验不明确。
- 候选人 C 行业相关但核心技术不匹配。

验收标准：

- 排序与人工预期基本一致。
- 每个候选人有总分和六个默认分项评分。
- 每个评分项有证据、缺口或待确认说明。
- 风险点能生成对应面试追问。

## 5. 安全测试

| 场景 | 验收标准 |
| --- | --- |
| 本地模式 | 原始简历不离开本地环境 |
| 脱敏 API 模式 | 姓名、电话、邮箱、地址、公司名、项目名、薪资被替换为占位符 |
| 导出行为 | 短名单和面试准备表导出写入审计日志 |
| 权重修改 | 操作者、修改内容和时间写入审计日志 |
| 模型调用 | 模型版本、提示词版本和任务 ID 可追溯 |

## 6. 性能测试

MVP 性能目标：

- 1 个项目需求 + 50 份简历：端到端匹配在 2 分钟内完成。
- 1 个项目需求 + 200 份简历：端到端匹配在 5 分钟内完成。
- 单个候选人详情页加载在 2 秒内完成。
- 导出短名单在 10 秒内完成。

测试时应记录硬件环境、本地模型、向量库、简历数量和平均简历页数。

## 7. 合规与文案测试

验收标准：

- 页面和导出文件使用“建议确认”“建议面试”“建议人工复核”等辅助判断表达。
- 不出现“AI 判定合格”“AI 判定不合格”“自动淘汰”“自动录用”等表达。
- 候选人分数旁边展示解释和证据入口。
- 用户能看到 AI 输出需要人工确认的提示。

## 8. 端到端验收场景

1. HR 输入 Java 后端项目 JD。
2. 系统解析出 Java、5 年以上、支付系统、日语沟通、到岗时间等条件。
3. HR 修改权重并确认项目需求。
4. HR 导入 100 份匿名日文简历。
5. 系统完成解析、脱敏、向量化和入库。
6. HR 运行匹配任务。
7. 系统在 5 分钟内生成候选人短名单。
8. HR 打开排名前 5 的候选人详情。
9. 每名候选人的评分都有证据、缺口和风险点。
10. HR 生成面试问题并导出短名单 CSV。
11. 导出行为和模型版本写入审计日志。
