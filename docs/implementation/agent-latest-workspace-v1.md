# Agent 最新动态工作台

日期：2026-09-07。基于信息整理与推广 v1，数据库版本 46。

默认启动进入 Agent，主体先展示案件与人员的最新动态，底部始终显示紧凑操作栏；选中案件或人员也不展开聊天框。输入区只在“当前对话”显示，并保留未发送草稿。右侧承载批量整理、资料与推广预览及案件详情；已有人员、案件资料的修改跳转完整页面；人员“是否自社”提供右侧下拉框自动保存的快捷例外。左侧导航仍可打开完整候选人、面试、案件和审核页面。

## 操作流程

- 邮件 / 微信消息：点击“粘贴消息 / 批量整理”，预览分段后整理；结果刷新到最新动态。单条失败可编辑重试。也可把 Agent 输入框的长文本转入批量整理；已有未完成批次不会被覆盖。
- 案件找人 / 推广：从案件动态进入找人或介绍工作区；未确认案件先核对资料，沿用既有案件模板配信。
- 人员找案件 / 推广：从人员动态进入侧边人员工作区，直接生成模板介绍，或一次点击完成本地初筛与云端案件评估。
- 查看动态即标为已读；“稍后处理”独立保留，查看不会将它移除。同一记录的新版本或状态更新会重新成为未读。
- 默认按本机日期显示今天的动态，可切换最近 7 天、30 天或全部时间，统一按动态时间倒序；已读只改变标记和数量，不改变列表位置。稍后处理不受时间窗口限制。较旧原始邮件新导入时额外展示原始信息日期。
- 当前记录高亮与右侧实际打开的对象同步，关闭详情时取消高亮。筛选后当前对象不在列表中时显示说明，右侧继续保留详情。标为已读不会切换处理对象，也不会把业务标为完成。
- 阅读状态下拉框默认“未读”，支持“已查看”和“全部状态”，与类型和日期共同筛选。本轮操作转为已查看的记录暂留原位，主动刷新或更改筛选后收起。整张卡片支持点击、键盘 Enter / 空格打开；悬停反馈与蓝色选中高亮分开，未读用橙色标签，已查看用灰蓝色标签。
- 后台新记录和新版本先显示更新提示，点击“更新列表”或“刷新动态”后合入列表，保留当前对象。同步已读及稍后处理标记不触发重排；旧版本确认仍由 Main 拒绝。
- 最新动态与当前对话可以切换；紧凑操作栏可粘贴消息或打开对话，未发送输入显示“继续未发送的草稿”。最新动态中的找人 / 找案件、生成介绍动作保留在卡片上。关闭右侧面板、前往其他业务页后返回，未发送输入和批量整理内容在当前应用会话内保留。

## 数据与行为

`business_feed_marks` 通过案件 / 人员外键关联现有记录，保存版本摘要、已读时间与稍后处理状态，纳入加密数据库、备份变更追踪和删除级联。读标记不改变业务审核或人员可推广状态。Main 拒绝旧版本的确认和附带未知字段的输入。

动态由现有资料和历史版本投影，每个案件 / 人员显示一条当前动态；支持展示已有记录的字段变化、人员推广状态和案件归档 / 恢复。首次案件确认显示“新案件”，真实生命周期事件才显示状态变化。最新动态工作列表仅展示当前有效案件和待营业人员；已入场、不可营业及归档状态优先于已读暂留和稍后处理规则，状态更新后立即退出列表。

动态卡片只传递已有的受控业务引用。Agent 继续由 Main 重新获取并脱敏当前工作区证据。批量整理沿用现有摄取管线与失败重试；模板复制、默认邮件客户端手工发送继续沿用原边界。

## 本轮边界

本轮落地统一入口和最新信息处理方式。案件目前仍沿用有效 / 归档生命周期，自动过期、募集结束、暂停募集等业务状态尚未扩展；今天是首页默认展示窗口，不会将旧案件自动判定为失效。不同来源的同一案件 / 人员尚不具备完整的语义归并，动态更新基于系统中同一记录的版本，不宣称已经自动识别所有微信后续消息。长列表当前按类型和时间筛选、最多渲染 80 条，大规模真实数据性能仍需试点评估。应用退出后不会恢复尚未导入的粘贴原文。

## 紧凑操作栏调整（2026-09-07）

最新动态默认收起完整 Composer，仅显示“告诉 Agent 想处理什么…”和“粘贴消息”。选中明确的案件或人员后显示处理对象名称和匹配 / 介绍快捷动作；关闭面板恢复紧凑状态。进入对话时聚焦输入框，发送后由完整对话承接进度和结果。草稿与附件在视图切换期间保留，紧凑入口显示继续草稿提示。

人员面板的选中记录与 Agent 引用同步，删除或失去当前记录时不会自动回落到另一人。打开案件或人员引用时重新设置当前案件上下文，避免沿用旧案件。这里的对象名称只用于本地展示，发送仍采用已有的受控引用与 Main 脱敏逻辑。

本轮全量 76 文件 / 728 测试通过。实际 Electron 窗口验证了首页收起、人员面板展开、关闭后收起，以及进入完整对话后输入框聚焦；没有提交云端请求或发送消息。日志和实际界面截图见 `output/implementation/agent-context-composer-2026-09-07/`。

## 人员与案件评估修正（2026-09-08）

当前人员作为本机会话引用单独保留。先打开人员，再打开案件，发送时会同时携带两者；清除人员后才恢复全人才池匹配。明确问“这个案件适合他吗”但未指定人员时，先要求选择人员，不运行全人才池搜索。编辑历史消息创建分支时不继承当前人员，避免把分支点之后的选择带回历史。

指定人员的任务保存 `candidate-profile` 绑定及资料版本，在检索前限定人员，重试和排队后执行都核对版本。单人评估保留零命中及硬条件不满足的依据；普通人才池搜索仍过滤不满足的人选。人员找案件只返回该人员资料命中的有效案件，不退回全量案件列表。卡片明确标记“指定人员”。

本机显示姓名；同名资料增加资料编号区分。姓名映射只发生在 Renderer，匹配模型仍接收脱敏的候选人编号。结果超过三个案件时默认折叠其余卡片。右侧首先展示技能、单价、地点、远程和开始时间；案件正文直接读取本机完整脱敏内容并保留段落；全部字段按需展开，编辑进入传统案件页面。

评估中的组合技能拆分核对，Java 的证据不能证明 SQL。无来源的负面判断转为核对问题，发现无依据或矛盾时撤下确定结论。历史卡片采用相同检查，旧评估文字可展开查看，并从后续模型上下文中移除其失效结论。相关度分数只表示本地排序指标。

验证覆盖：Main IPC 的缺失人员澄清、指定人员绑定及后续对话恢复、人员找案件禁止无范围回退；Renderer 的先选人员再选案件；技能证据冲突及 Java/JavaScript 边界；指定人员的零命中及失败证据；加密数据库中的人员绑定及会话引用往返。实际界面检查使用已有本机记录，未为验收发送新的云端请求。

## 最新动态与详情展示修正（2026-09-08）

最新动态始终使用紧凑操作栏，打开案件或人员后也不展示聊天框；聊天输入仅在当前对话中提供。阅读状态选项依次为全部状态、已查看、未读，默认仍选择未读。

案件编辑区与来源区不再共用同一个 React key，切换案件会重建对应详情，避免残留多个编辑标题。人员详情先展示基本条件和技能标签，超过八项技能按需展开，项目经历在人员预览中整体折叠，展开后逐项查看；编辑表单放在传统页面，字段来源按需查看。列表内人员技能摘要限制两行。原始 Excel 简历复用表格预览，保留单元格位置及合并关系，并提供工作表选择和缩放。

## 当前营业状态与有效工作列表（2026-09-08）

从动态选中人员后，右侧仅展示该人的资料、营业状态和推广操作，移除重复人员列表、搜索和批量选择控件。完整人员工作台默认筛选待营业人员，切换全部营业状态后可找到已入场或不可营业人员并恢复状态。

新导入且尚无人工营业状态的人员进入待营业队列；近期可入场仍属于待营业范围。HR 可以在完整人员工作台顶部下拉框选择待营业、近期可入场、已入场或不可营业并保存，无需额外复选确认。未确认资料也能维护营业状态，使用审核版本及当前资料版本校验防止旧数据覆盖。此操作只调整实际营业状态；人员导入后默认即可推广和匹配，无需额外确认。

传统案件页面使用有效 / 无效下拉框，未完成资料审核的案件也能设为无效。有效性与资料确认分离，确认字段不会自动恢复已标无效案件。状态持久化后，最新动态排除不可用记录；既有资料、历史和恢复入口继续保留。阅读状态下拉框的“全部状态”只表示全部阅读状态，不会重新混入无效业务资料。


## 统一人员预览与编辑跳转（2026-09-08）

Agent 人员概览统一打开人员预览面板。所有有效人员记录都展示推广模板、语言和文案预览；导入后即可复制、打开邮件或找案件，不再显示推广状态待确认或要求人才库准入。仅已入场、暂停营业等明确停用状态影响业务操作；旧资料或模板版本仍须刷新。

右侧营业状态以单行标签显示，人员资料与推广文案只读；“是否自社”按 HR 要求允许直接选择并自动保存。“查看 / 编辑完整档案”进入传统候选人页面；“管理状态”和“编辑文案与模板”进入完整人员工作台，并定位当前人员，后者同时携带模板和语言。右侧不呈现状态保存、人员审核或模板编辑表单。完整页面的营业状态选择和保存按钮在同一行。

推广区采用独立标题、两列模板与语言选择、文案预览和一行三个操作。项目经历默认整体折叠，减少推广区之前的滚动。动态卡片的已读状态只在顶部保留，移除底部重复的“已查看”按钮。


## HR 业务优先原则（2026-09-08）

核心业务只有案件找人、人员找案件。优先让 HR 快捷完成业务，非必要不新增功能、状态或确认步骤。导入人员即产生可用的业务资料；需要改数据时到传统人员管理页面编辑，右侧查看和预览，仅“是否自社”可直接修改并自动保存。推广工作台不再放人员审核表单。


## 人员找案件云端评估与返回位置（2026-09-08）

“为此人找案件”现在先检查技能 / 角色的词法依据及明确硬条件，日期或地点重合不能单独入选。取本地排序前 5 条，在一次受控云端调用中评估人员与各案件的专业适合度。沿用默认 Agent 模型和现有本地脱敏、DLP、审计通道，不新增用户确认或模型设置步骤；原始文件、本地身份字段、业务内部编号不进入评估投影。

云端返回的要求引用必须属于对应案件，经历依据必须出自同一人员。没有有效来源依据时撤下确定推荐；未知硬条件不能升级为较强适合。按较强、可能、信息不足、较弱排列已评估结果，并展示理由和核对项。未评估记录逐项标明本地初筛；不可用或失败不会假装云端完成。请求有 45 秒上限和远程取消，同一人员重复点击合并；返回时检查人员版本与案件有效性。

最新动态的选中记录独立于右侧详情导航保存。人员匹配结果中的案件选择单独记录，打开案件不会清除人员动态高亮；“返回上一级”恢复人员匹配面板、结果选中和滚动位置，不再次请求云端。人员切换期间迟到的回复只存回原人员，资料版本变化后不显示旧评估。


## 列表操作定位与请求防重（2026-09-08）

人员动态中的“查看详情”定位右侧资料顶部，“生成介绍”定位推广预览，“找案件”定位请求进度并在返回后展示匹配结果。“稍后处理”继续标记该条记录，同时显示其资料，不新增业务步骤。案件动态对应打开案件资料、匹配结果或介绍页面，再次点击同一入口也重置该页的阅读位置。定位只滚动右侧，不改变中间列表的滚动与选中。

人员匹配期间同步禁用列表和右侧的匹配按钮，显示灰色与“正在匹配”；重复意图直接丢弃，不在当前请求完成后排队重跑。请求成功或失败均恢复按钮。对话内案件卡片的“跑匹配”同样绑定当前请求状态；发送处理函数以同步请求引用阻止快速连点。

专项验证：列表到右侧的定位、重复提交拦截、失败后重试、返回时选中及滚动位置保留，以及同页重新定位与普通重渲染保持位置。实际 Electron 中验证资料 / 推广预览 / 匹配结果的定位和调用期间两处按钮灰色禁用。


## 案件找人与人员找案件统一（2026-09-08）

案件列表和案件详情的“找人”直接启动当前案件的人员匹配；不再进入包含所有案件选择器及旧结果的查看页。右侧仅展示当前案件的要求、匹配进度、人员结果和资料入口，移除面向 HR 的导入检查记录。

新入口对有效人员做技能 / 角色依据及明确硬条件的本地筛选，取最多 5 人经现有脱敏与云端匹配评估通道做一次批量评估。显示适合度、原文依据与待确认项，按适合度排序；未评估或失败显示本地初筛，不假装完成 AI 评估。请求防重、45 秒超时、远程取消及期间版本 / 停用检查与反向流程一致。

列表和右侧按钮共享请求状态。打开结果中的人员再返回，保留案件选中、人员选中、匹配结果和滚动位置，不重新调用云端；两个方向均可直接继续核心业务。

本轮验证：全量 80 个测试文件、783 个测试通过；类型检查和中文界面文案检查通过。实际 Electron 中 Java 案件筛出 9 位人员、云端评估 5 位，约 27 秒返回；列表 / 右侧按钮禁用、查看人员后返回保留高亮与滚动位置均已验证。


## HR 自社属性与匹配过滤（2026-09-08）

传统人员档案编辑新增“是否自社”下拉框：未设置 / 自社 / 非自社。默认空值，简历导入和云端抽取不推断该属性；历史档案缺少该字段时按空值读取。属性随人员档案版本加密持久化；旧调用不传此属性时保留 HR 原选择，显式空值可清除。右侧人员资料第一行提供同样的下拉框，选择后自动保存，不增加保存按钮；保存期间禁用并防止重复提交，失败保留原值。这是 HR 明确要求的快捷修改例外，其余资料仍在人员管理页编辑。属性通过单独接口更新，不重新提交其它资料或身份映射；成功后刷新档案版本并清除旧匹配结果。

案件的商流、所属限制或要求明确为自社 / 貴社社員のみ / 貴社社員まで等时，共用本地检索在评分及云端评估前只放行 `isOwnCompany === true` 的人员。非自社与未设置均排除；没有自社要求时三种状态都可正常匹配。“自社优先 / 歓迎”和允许协力公司人员的描述不等于自社限定。规则同时适用于案件找人、人员找案件和对话检索。

### 案件正文阅读排版（2026-09-08）
