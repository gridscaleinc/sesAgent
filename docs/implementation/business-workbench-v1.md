# 信息整理与推广工作区 v1

更新：2026-09-08。实现位于当前工作树，数据库 Schema 46。

本次围绕 HR 的两条日常业务改造：从邮件和微信中的案件信息找人、配信；从微信中的人员信息找案件、推广。把整理大量消息作为默认入口，复用原有脱敏、AI 抽取和案件模板能力。

## HR 操作路径

1. 打开“信息整理与推广 → 信息整理”，粘贴案件、人员消息。邮件 / EML 按钮进入已有导入流程。
2. 点击“预览分段”，核对每段内容。可返回编辑，也可直接修正单段。支持一次最多 100,000 字、200 段；每段执行上限为 3,900 字，超长段完整保留供修改，不截断。
3. 点击“整理未完成的内容”。结果显示新增案件、人员、已有记录和需要处理的内容。单段失败不阻止后续段，重试不重复成功段；可在当前段结束后暂停。
4. 案件从结果进入“案件配信 / 找人”，沿用已有中文、日文模板，编辑、复制或打开默认邮件客户端，也可进入既有匹配流程。
5. 人员导入后即可推广、找案件，也直接参与案件找人。无需先审核字段、确认推广状态、加入人才库或经历招聘面试；需要修正资料时，由 HR 到传统人员管理页面编辑。HR 明确设为已入场或暂停营业时才从当前业务范围排除。
6. 选择微信群简版或邮件详细版，选择中日文，编辑介绍。可单人复制、选中 1–20 人批量复制、打开默认邮件客户端，或为此人查找案件。默认介绍使用匿名编号。
7. 模板可以编辑并在本机保存。复制历史与资料版本关联；“未复制或资料有更新”筛选帮助找到待处理人员。

## 已完成的行为与约束

- 启用原有业务 Agent 功能时，默认打开新的信息整理工作区。保留原 Agent 和原业务页面。切换页面保留未完成的本批输入、人员文案编辑；退出应用后的原始批次恢复尚未实现。
- 信息整理执行使用专用 `intakeOnly` 标记，进入已有业务抽取与本地脱敏流程；识别不明确的消息也不会掉入普通对话规划。服务缺失时返回错误。
- 人员推广模板使用当前字段确定性填充，导入后即可复制或打开邮件；AI 在前面的消息识别 / 抽取环节复用。当前没有新增“自由生成多种人员营销文案”的云端按钮。
- 导入自动生成当前业务资料，保留“本机导入”来源，不伪造 HR 复核记录。已有导入记录在启动时补齐；资料更新后继续可用，不新增再次确认流程。暂停营业或已入场的明确状态仍生效。
- 人员找案件先以技能 / 角色和硬条件本地筛选，最多取前 5 条通过既有脱敏通道进行一次云端批量评估。按云端适合度排序，展示项目依据、理由和待确认项；云端不可用、失败或部分返回时，对未评估记录明确标为本地初筛。当前初筛仍是本地词法检索，不声称已接入反向向量检索。
- 复制与邮件交接前，Main 检查当前记录是否可用、资料版本、模板版本及直接识别信息。文案默认匿名，本地身份字段不直接放入介绍。
- `mailto:` 仅包含编码后的主题和正文；收件人和最终发送由 HR 在邮件客户端处理。复制历史只有版本、模板、语言、时间和正文哈希等元数据；复制或打开邮件不标记为已发送。
- Schema 45 增加业务状态、人员模板与复制记录三张表，包含备份修订触发器；删除人员时业务状态和复制记录一并清理。
- 同时修复案件新建后匹配数据未刷新的路径，补充 `【単価】80万円` 和人员 `稼働：2026年10月` 等常见标签识别。

## 后续工作

按业务价值继续推进：批次草稿加密持久化和重启续作、不同来源同一人员 / 案件的重复与更新比对、真实 HR 数据下的抽取准确率与整理耗时验收、人员反向检索的语义召回效果评估、推广后反馈与跟进。

现有 Gmail 同步条数上限和云端请求超时问题不包含在本次实现中；该工作区也没有新增自动读取完整微信历史或自动群发能力。
