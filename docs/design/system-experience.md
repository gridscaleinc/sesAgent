# 无感后台学习与系统经验

HR 正常进行匹配、修改面试问题、保存面试记录、准备和复制介绍文即可。系统在后台整理经验，不增加学习任务，不要求填写提示词。设置中的“系统经验”是可选入口，用于查看方法、来源、版本和使用情况，以及暂停学习、停用或恢复经验。明确的“AI 工作规则”保持独立，案件条件、事实证据和隐私约束优先于自动经验。

## 已接通的业务闭环

- 匹配证据核对：案件找人、人员找案件和案件内简历评估保存输入、输出、人员/案件/规则版本及实际调用的经验版本；明确的判断理由和后续专业反馈可以用于学习。
- 面试问题：依据简历、案件要求、已有问题和已记录回答出题。HR 可以直接改写题目并正常保存，系统记录修改前后和原生成来源；仅勾选或取消不形成语义偏好，也不代表已经问过。
- 人员和案件介绍文：打开时立即显示本地文案并建立来源记录。有适用的已验证经验时后台生成改进表述；HR 开始编辑、复制或选择邮件操作后，不以迟到结果覆盖文案。手动重新生成的结果也不会被先前后台请求覆盖。只有采用时记录修改，不把复制/打开邮件当成已发送。

## 从记录到方法

1. 记录原生成与已保存的修改/反馈。页面进入视口才算展示，打开详情单独计数；点击、未回复、单价、档期、意向、案件关闭或无原因的通过/失败不能直接成为技术能力标签。必需技能缺少简历依据时，可以判定不满足当前案件要求，但不能自动学习成此人永久不具备该技能。
2. 模型从明确的专业说明或采用后的实质改写中提炼观察，必须引用原记录连续原文，并关联原有案件要求。事实更正、标点修改、无理由勾选不用于总结习惯。
3. 同一方法、意图、关键词和适用范围，需要五个独立业务对象的支持。匹配/面试要求不同人员与案件；介绍文可使用不同的单独人员或单独案件。三个案例用于起草具体业务方法，另外两个独立案例留作验证。
4. 模型生成标题、操作步骤和注意事项，必须逐字引用三个训练案例。应用校验来源和结构，并拒绝身份占位符、联系方式、执行代码、数值门槛及削弱证据/隐私约束的指令。自然语言方法作为数据传入任务，不具有修改应用权限或执行代码的能力。
5. 在两个留出案例上，分别使用当前方法和候选方法验证。证据核对、面试和介绍文调用正式生成服务。生成仅使用反馈前快照；HR 的改写和结果不进入待比较的生成输入。比较器交替接收 A/B，须引用反馈和输出原文。两个案例都改善且没有事实、硬条件或证据退化，才进入试用；平局或失败不发布。排序偏好则对反馈前保存的同一候选池做确定性回放，两个案例都提高目标的同层级排名才启用；不依靠模型自评排序效果。
6. 后续新的五个独立、未消费的纠正样本可触发方法改版。验证新版本期间继续使用此前已验证的版本；额度不足时持久保存进度。已使用的样本不会反复触发相同改版。
7. 三个独立的明确正向效果支持可以将试用版本转为稳定使用；改写本身不能证明原方法有效。三个明确反例触发撤回并锁定。用户主动停用的经验不会自行恢复。

基础模型参数不变。方法以可读的结构化步骤保存于加密数据库；当前不在文件系统中落地包含业务记录的 SKILL.md。方法版本、来源引用和效果归属保留在数据库中，便于追踪与恢复。

## 推荐顺序与客户偏好

明确说明“为什么这类合适人员应优先”的专业反馈，可以产生排序方法。目前支持六个有界特征：相关项目证据、本人独立责任、交付成果、业务领域经验、项目阶段经验、沟通协调职责。每个特征最多加四个排序分，同类不叠加，总增量最多十二；原匹配分、硬条件、证据结论和待确认项不改写。排序先保留推荐/待确认层级和证据匹配等级，再保留明确 HR 规则优先级，最后在同层级内应用经验。排除人员、弱匹配和只有一个对象的评估不附加排序作用。

案件找人和人员找案件在截取结果前应用偏好，云端证据核对完成后再次按相同边界排序。学习回放使用当时保存的最多六十个比较对象；不能把这一回放当作整个库的召回率验证。偏好必须有明确原文、三个训练来源和两个独立留出来源。适用范围包含使用人、语言以及客户或案件类型，不跨客户泛化。列表显示采用的经验版本和当前简历中的依据；没有证据不加分，也不作负面技术判断。

## 可复用面试题库

HR 正常保存准备好的面试问题即可进入后台整理队列。模型从已保存的问题中提炼通用问法、能力主题和判断依据，移除旧人员、客户、项目身份和事实，保留精确来源引用。模板与“经过五例验证的业务方法”分开管理：单条合法来源可成为可用模板，三次采用显示常用，但这些状态不证明问题质量或招聘成效。

生成新问题时，最多提供八条符合当前使用人、语言、客户/案件类型与要求关键词的模板。模型必须结合当前简历与要求改写，并返回被使用的模板编号；应用校验编号、版本、当前证据和要求。保存时只相信原生成记录的题库归属，不能由界面传入的任意编号建立归因。每个题目保留采用和实质改写记录，取消选择会撤去对应采用。

设置中的题库支持搜索、主题筛选、查看采用/改写次数、停用和恢复。来源删除或替换后，没有有效来源的模板立即停止调用。模板、来源和采用记录存入 Schema 55 的三张加密数据库表，人员/案件/面试删除继续受外键和生命周期管理。

## 逐题回答与主动发现

保存面试反馈后，后台将原文与已选问题关联，记录回答原文、摘要和剩余确认事项。回答状态是已有记录、部分回答或未找到记录；不代表技能核验通过。每次保存绑定面试记录、题目和决定状态的内容哈希，记录变化后旧关联立即停止展示，旧请求也不能回写。匹配结果和面试反馈界面可展开查看回答依据；后续出题会读取这些结构化记录以避免重复询问。题库展示实际有回答记录的采用次数及部分回答数，不能将未回答解释成问题无效或人员能力不足。

人员面试结论页和历史轮次也读取本轮已保存的回答依据。复试复盘只列父轮次实际保存的待确认项，不补默认关注项，不按条目位置推断已确认；从本轮清单移除也不等于问题已经解决。简历登记技能与面试结论分开表述，准备状态按真实登记信息展示。旧版普通字符串题目编号与 UUID 题目编号均可关联回答，出网前统一转换成请求内临时编号。切换案件、轮次或记录版本时立即撤下旧回答；请求失败或旧请求迟到时不保留或覆盖当前证据。

本地机会发现每十五秒在空闲时检查，使用匹配策略版本、资料版本、人员营业状态、业务推进、规则、客户和经验版本判断是否需要重新筛选；每次最多处理五个案件，每五十个人员让出主线程。新案件、人员资料和条件变化均会触发重新检查，按已有规则和有界排序经验列出每案最多五个机会。已排除、不可用人员和正在推进的同一组合不进入新机会。界面注明本地依据，打开后进入正式匹配评估。不会自动联系人员或客户，也不为每条导入调用模型。

相同内容指纹不会反复提醒；已忽略组合仅在相关资料或结果发生实质变化后重新出现。列表读取时再次检查人员和案件版本、营业状态与规则修订；案件关闭、资料变更后旧推荐不再展示。详细模型评估仍按现有流程执行。

## 题库版本与客户身份

题库在同一使用人、业务范围、语言、能力主题和关键词内比较相似问法。模型须引用保存的问题；只有明确同义且现有问法不劣时才建立合并关联、停止重复条目的自动使用，原始来源与历史采用归因保留原编号。HR 可以恢复被合并的问法；手动恢复后不会自动再次合并。语义不同的问法不会因共享关键词被合并。

同一模板版本收到五个独立人员/案件的实质改写后，以三条记录起草新模板、两条留出记录比较。两个案例均改善且没有事实或条件退化，才替换为新版本。保存比较说明、版本文本和来源哈希，支持查看及恢复。来源修改或删除后不能用失效依据恢复历史版本。暂停或锁定的模板不会自动改版。后台整理和版本比较共用学习额度，模板比较不是实际面试效果的随机实验。

可选的“客户名称与别名”入口以期望版本控制保存同一客户的正式名称与别名，阻止一个名称同时归属两个客户。更名保留旧名称为别名；后续可解除别名关联。历史经验保持原始范围，新调用通过明确别名匹配旧客户范围，避免改写历史归因。名称相似本身不会触发自动合并。

Schema 56 增加客户身份、逐题回答、主动机会、题库版本和增量检查记录，均存入现有加密库。回答和机会绑定业务外键，题库历史绑定模板；新增表纳入备份修订触发器。

## 范围和效果

匹配和面试经验优先绑定明确记录的客户；没有客户时绑定行业/岗位类别，否则只适用于当前使用人。介绍文表达偏好绑定使用人、语言和简洁/标准风格。范围来自业务字段和明确客户标注，不由模型猜测客户身份。不同使用人、语言和风格不会互相套用。

“系统经验”支持按个人、客户、案件类型筛选，显示具体步骤、当前验证状态、实际仍在使用的版本以及来源和历史。效果面板分别展示基本方法与采用经验的记录，包括采用次数、修改频率、平均文字改动幅度、重复问题比例和反馈数量。匹配任务以明确反馈数量记录，不伪造文案采用数。样本不足时不判断改善。

趋势按适用范围和任务比较最近十四天与此前十四天，两段各至少五个独立对象才显示改善/下降方向。专业判断的明确纠正、经过验证的专业观察、采用后实质改写可以进入指标；商业原因、未回复和无说明勾选不会成为技术质量结果。后台另按实际采用的同一经验版本监测最近十个独立对象：后五条至少四条负面/改写、前五条至多一条时，自动停用该经验或题库模板。恢复创建新版本，旧版反馈不会立即将恢复版再次停用。时间趋势仅供观察，自动停用按版本归属执行。

这些是业务使用指标，不是准确率，也不是随机对照实验。模型生成和评审使用同一配置模型，可能存在共同偏差；五个案例等阈值属于初始工程策略，不代表统计显著性。系统具备逐步优化机制，实际招聘成效需要持续真实业务验证。

## 运行、隐私和生命周期

应用打开、空闲至少三十秒时整理，通常五分钟检查一次。每轮优先整理最多两场已保存面试记录，再处理最多十二条事件、一个候选方法和三条题库来源；题库最多执行一次改版或同义比较。开始前台操作/生成或退出时中断；下次空闲继续。默认后台每天最多十六次调用，可设置零或三至六十次，UTC 日界重置。失败也计入额度；一次 A/B 比较预留三个调用。起草业务方法另外计一次，每条题库归纳计一次；确定性排序回放不产生模型调用。后台学习开启时，即使模型额度用尽，本地效果监测仍运行；暂停学习则停止自动整理和监测。正常业务中的自动介绍文生成走已有生成服务，不占后台整理预算。

所有云端提炼、生成与评审复用现有本地姓名识别、脱敏、DLP 和 Cloud gateway。发送到模型的内部 UUID 使用请求内临时别名，返回来源必须属于本次输入；业务原文仍经过完整隐私检查。来源、修改前后及运行快照保存在现有加密数据库，不建立第二套明文业务存储。Schema 53 增加五张经验表；Schema 54 在保留数据及外键的前提下允许单独案件介绍文记录。人员、案件和面试删除会级联移除运行、事件与观察；来源被修改、替代或删除后，相关经验立即失效，历史恢复也必须重新校验有效依据。

复制/邮件动作前校验生成来源属于当前对象、使用人及有效资料版本，防止错误归因。学习暂停只停止新整理，已有经验可逐条管理。版本控制使用期望版本检查，恢复会创建新版本而不覆盖历史。

## 验证入口

- `npm test`、`npm run typecheck`：业务、界面、隐私边界与类型回归。
- `npm run test:system-experience`：加密数据库中匹配/面试提炼、回放、试用、反例撤回、预算、归因和来源失效。
- `npm run test:system-experience:v2`：介绍文真实方法生成、后续改版、验证期间旧版服务、语言/风格/使用人隔离、问题改写、指标和删除失效。
- `npm run test:experience-growth`：客户偏好五例学习、同级排序回放、范围隔离、保存问题到通用题库、版本归因、持续监测停用、恢复和重启/删除生命周期。
- `npm run test:business-growth:v3`：回答来源及更新失效、客户别名隔离与解除、题库留出比较改版和恢复、同义合并、推荐忽略和版本失效、重启与删除。
- `node scripts/run-experience-live.mjs scripts/verify-growth-live-v3.ts`：仅合成资料的真实模型逐题回答、题库起草、独立比较和同义判断；报告为 `output/system-experience/growth-v3-live-report.json`。
- `npm run test:schema-upgrade`、`npm run test:schema-v37-agent`：旧库升级和外键一致性。
- `npm run test:system-experience:live`：通过当前已登录 AI 服务和正式隐私路径，仅使用合成业务记录运行真实模型验收。最多十二次调用，九分钟请求期限，十分钟进程上限。模型返回非法 JSON 时仅允许一次新请求重试，仍受总调用上限约束；不修补或放行非法结果。结果保存到被 Git 忽略的 `output/system-experience/live-report.json`。凭据留在系统凭据库，不写入报告；不修改真实业务库。需要先在应用中登录 AI 服务。真实服务可能返回平局或被证据校验拒绝，不能以测试替身结果替代。

正式安装包仍须发行方提供 Google Desktop OAuth 配置。缺失时发布构建按现有产品门禁停止；开发版与隔离数据库验收可以继续。不能用虚构配置或降低发布门禁代替这一依赖。
